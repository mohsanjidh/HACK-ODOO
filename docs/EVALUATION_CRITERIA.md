# 🏆 OFFICIAL EVALUATION CRITERIA & RULES
*Odoo x Make-A-Ton 9.0 Kochi Hackathon 2026*

---

## 🟢 MUST-HAVE CRITERIA (Mandatory)

1. **Dynamic & Real-time Data Sources:**
   * Avoid relying on static JSON files (except for initial early prototyping).
   * All screens must interact dynamically with a real database backend in real time.
2. **Clean & Responsive UI:**
   * Consistent design language (Teal color scheme `#017E84`, proper spacing, responsive on desktop and mobile).
3. **Robust Input Validation:**
   * Strict validation for passwords, unique emails, numeric types, and state transitions.
4. **Intuitive Navigation:**
   * Clear menu placement, role-based visibility, accessible actions.
5. **Proper Git Version Control:**
   * **Crucial Rule:** One member managing the repository is **NOT** enough. All active members must commit and push regularly from their own git configurations.

---

## 🟡 NICE-TO-HAVE CRITERIA (Winning Bonus Points)

1. **Local Database & API Design:**
   * Clean backend REST APIs, well-modeled relational schemas, and a structured local database.
2. **Offline & Local-First Reliability:**
   * **Plan for offline or local solutions — do NOT rely entirely on internet connectivity or cloud-based tools.**
   * If venue internet drops during live demo, the entire system must still function seamlessly.
3. **Code Comprehension & Integrity:**
   * Understand all code snippets thoroughly before using them. No blind copy-pasting. Be prepared to defend your code during Q&A.
4. **Value-Driven Technology:**
   * Use proven, fast, reliable technologies that add real value (e.g. FastAPI + SQLite + Vanilla JS for instant sub-2s responses).

---

## 🔴 CRITICAL RULES FROM EVALUATOR (Bhavya / mebh-odoo)

* **Single Branch ONLY (`main`):**
  * All code must live on the `main` branch.
  * **Do NOT create separate branches, feature branches, organizations, or multiple repos.**
* **Hourly Push Requirement:**
  * Every team member must push their code to `main` **at least once every 1 hour**.
* **Individual Q&A Evaluation:**
  * In the afternoon, the evaluator will conduct a Q&A session asking questions **based on each member's individual git commits**.
  * Every member must know the code committed under their name.
